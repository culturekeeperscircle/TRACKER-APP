# TCKC tracker landing page

Conversational landing page for the Cultural Resource Threat Tracker. Next.js 15 app router, Vercel AI SDK, Anthropic Claude Sonnet 4.6, Supabase.

## What it does

1. Gates every visitor on profession + state (no email, no name, no IP, no fingerprint).
2. Streams a chat answer grounded in the 800+ tracker entries via Postgres full-text retrieval.
3. Logs every turn to `chat_turns` for analytics, with the retrieved entry IDs so we know what the model leaned on.
4. Refuses on no-retrieval and on off-mission questions; never speculates outside the corpus.

## Locked decisions (2026-05-07)

| Decision | Choice | Where to override |
|---|---|---|
| Profession taxonomy | 18-bucket fixed list with `other (specify)` free text | `lib/professions.ts` |
| Location granularity | State required, ZIP optional | `lib/states.ts` + `components/Gate.tsx` |
| Anonymity posture | No email, no name, no IP. UA hashed for abuse-detection only. | `app/api/session/route.ts` |
| Voice constraints | TCKC documented voice, severity rubric, URL citations required, refusal-on-off-mission | `lib/system-prompt.ts` |

## Deploy

1. Push the repo. From Vercel, import `culturekeeperscircle/TRACKER-APP` and set the root directory to `landing/`.
2. Add env vars: `ANTHROPIC_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`. `NEXT_PUBLIC_SUPABASE_URL` defaults to the project's URL but can be set explicitly.
3. Add the custom domain `tracker.culturekeeperscircle.org`. Add the CNAME / A record at your DNS provider.

## Data flow

```
Browser → /api/session  → chat_sessions  (Supabase, service-role write)
                       → tckc_sid cookie

Browser → /api/chat     → retrieve(query, k=8)        Postgres full-text on entries
                       → buildSystemPrompt(...)
                       → streamText(anthropic('claude-sonnet-4-6'), ...)
                       → onFinish: insert chat_turns (user + assistant)
```

## Schema

Three tables added in migration `tckc_landing_chat_schema`:

- `chat_sessions` — one row per gated visitor
- `chat_turns` — every question and answer with `retrieved_ids`
- `digests` — per-profession State of the Union, generated by Phase 2 cron

Plus two views:
- `v_chat_volume` — daily session volume + distinct-profession / distinct-state counts
- `v_top_concerns_by_profession` — clusters questions by profession × state with most-retrieved-entry sample

## Phase 2 work (not in this MVP)

- Daily Vercel cron generates one digest per profession bucket; cache in `digests` table.
- Show the user their bucket's State of the Union as the first chat message after the gate.
- Email opt-in with a separate "weekly digest" subscription (will require an email column or separate `digest_subscribers` table).

## Phase 3 work

- Add pgvector embeddings for hybrid retrieval (keyword + semantic).
- Cluster `chat_turns` by topic, surface "top concerns by profession × state" on a TCKC-internal page.
- Personalize digests beyond profession bucket using prior question history.

## Risks accepted in MVP

- **Cost runaway.** No rate limiting yet. Monitor Anthropic usage daily for the first two weeks. Add `middleware.ts` token-bucket if abuse appears.
- **Cold-start retrieval.** Postgres full-text returns nothing for off-mission or vague questions; the refusal path catches this. Watch the `refused = true` row count in `chat_turns`.
- **Prompt drift.** The system prompt is in `lib/system-prompt.ts`; every change should be code-reviewed. No live editing via Studio.
